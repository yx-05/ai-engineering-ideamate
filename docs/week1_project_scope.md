# Project Scoping Document

| Field | Content |

| **Project Name** | **IdeaMate — Your Hackathon Brainstorming Teammate** |
| **Domain** | Software Engineering / Competitive Innovation & Hackathons |
| **Problem Statement** | Hackathon teams frequently lose critical opening sprint hours debating and diverging on project concepts. When an idea is finalized, it often suffers from one of two extremes: either technically unfeasible within a 24-to-48-hour development window, or too conventional and misaligned with official competition scoring criteria. AI engineering enables an evolutionary multi-agent ideation assistant that pairs divergent creative generation with grounded technical constraints, synthesizing robust concepts and scoring them directly against official judging rubrics. |
| **Evidence of the Problem** | **Evidence 1:** Hackathon case studies and post-mortems indicate that teams spend up to 20–30% of total competition time during initial ideation and pivot cycles, significantly reducing implementation and debugging bandwidth.<br>Source / citation: Komssi et al., *Hackathons in Software Engineering: An Exploratory Study*, IEEE Software.<br><br>**Evidence 2:** Post-event surveys reveal that teams frequently drop points on rubric-specific alignment (e.g., feasibility, sponsor track adherence, impact) despite having functional code.<br>Source / citation: Falk et al., *Understanding Hackathon Success Factors*, ACM SIGCSE. |
| **Initial Related Work (at least 3)** | **Study / solution 1:** General-purpose conversational LLMs (e.g., ChatGPT, Claude) used for open-ended prompt brainstorming.<br>Source / citation: Standard web/chat interfaces.<br>Key limitation: Generates unconstrained, generic concepts without awareness of a hackathon's strict 24-to-48-hour time limit or specific judging rubrics.<br><br>**Study / solution 2:** Static hackathon idea generators and project prompt repositories (e.g., Devpost showcase, GitHub topic lists).<br>Source / citation: Devpost Project Inspiration Gallery.<br>Key limitation: Fixed, static project concepts that cannot synthesize novel ideas across sponsor tracks or adapt to team-specific skills.<br><br>**Study / solution 3:** Multi-agent debate and consensus systems for collaborative design.<br>Source / citation: Liang et al., *Encouraging Divergent Thinking in Multi-Agent LLMs*.<br>Key limitation: Focuses on unstructured debate without grounded evolutionary crossover or automated verification against formal evaluation rubrics. |
| **Engineering Gap / Limitation** | Existing brainstorming systems are either entirely open-ended and unconstrained by competition timelines, or static catalogues that lack generative synthesis. No dedicated AI engineering solution synthesizes polarized personas (radical ideation vs. pragmatic realism) through evolutionary combination while being grounded in official hackathon rules and rubric constraints. |
| **Initial Project Objectives (2–3)** | **O1:** To design a multi-agent ideation pipeline incorporating contrasting agent personas (Realist vs. Wild Ideator), an evolutionary combination step, and an automated rubric-scoring evaluator.<br>**O2:** To develop the solution with document-grounded retrieval (RAG) based on official hackathon rulebooks, theme briefs, and judging criteria.<br>**O3:** To evaluate the quality of generated project concepts in terms of feasibility, rubric alignment, answer groundedness, and inference latency. |
| **Target Users** | Student software developers, university hackathon participants, and early-career engineers participating in competitive technology sprint events. |

| **Similar to EduAdvisor** | Uses document-grounded retrieval (RAG) over structured PDF documents and applies automated guardrails/filtering before delivering responses to the user. |
| **Different from EduAdvisor** | Moves beyond standard single-turn student Q&A by implementing a multi-agent dialectic architecture with evolutionary idea synthesis and automated score estimation against quantitative judging rubrics. |
| **Responsible AI Risks (at least 2)** | **Risk 1 — Technical Hallucination & Phantom APIs:** The model invents non-existent APIs, libraries, or unrealistic sensor integrations.<br>*Harm:* Teams base their core competition project on impossible dependencies and fail to produce a working prototype before submission.<br><br>**Risk 2 — Algorithmic Bias & Tech Stack Monoculture:** The ideation agents prioritize mainstream frameworks or buzzwords while penalizing viable alternative technologies.<br>*Harm:* Participants with non-standard technical backgrounds receive skewed or suboptimal recommendations. |
